# CLAUDE

A deployment management tool with a Go backend and VanJS frontend.

## Project structure

```
api-contract/        Protobuf API schema and code generation.
backend/             Go HTTP server, handlers, auth, engine, and storage.
frontend/            VanJS + Vite SPA.
docs/                Project documentation.
```

## Commands

- Backend HTTP-only server (HTTP/1.1 on localhost:8080): `OPENDEPLOY_HTTP_ONLY=true OPENDEPLOY_MASTER_PASSWORD_HASH=<argon2id-hash> go run . primary` in `backend/`.
- Frontend dev server: `pnpm install` then `pnpm run dev` in `frontend/`.
- Frontend build (embedded by Go): `go generate ./...` in `backend/`, or `pnpm run build` in `frontend/`.
- Proto codegen: `bash api-contract/proto_generate.sh` (requires `cleanproto`).

## Notes

- Installed/runtime data is stored under `/var/lib/opendeploy`; tests use OS-appropriate app data directories.
- API contract is defined in `api-contract/api.proto`. Go and JS models are generated by `cleanproto`.
- Binary protobuf encoding is used for all request/response bodies.
- Auth is passkey-only. Set `OPENDEPLOY_MASTER_PASSWORD_HASH` (argon2id hash from `authu.HashPassword`) to bootstrap the first passkey.
- Set `OPENDEPLOY_GITHUB_TOKEN` for private repo access.
- Primary cluster mTLS material is generated on first startup and stored as internal encrypted secrets; workers cache enrolled TLS files under `/var/lib/opendeploy/tls/`.
